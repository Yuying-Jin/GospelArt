网站邮件使用说明

网站的两条邮件渠道：订阅通讯（Newsletter）和"联系我们"表单。标有同工的部分所有人都可以看；标有管理员的部分需要登录服务后台，记录了每一项是怎样配置的。

邮箱一览

同工

网站只使用 sjgart.org 域名下的三个地址。它们都没有自己的收件箱：寄到这些地址的邮件由 Cloudflare 转发到负责人的邮箱。

1订阅通讯

同工

读者怎样订阅

  1. 读者在网站页脚输入邮箱，点"订阅"。
  2. EmailOctopus 从 newsletter@sjgart.org 寄出一封确认信。确认信可能晚几分钟才到，也可能进垃圾邮件。
  3. 读者点信里的"确认订阅"按钮后，才正式加入名单。没点确认的人不会收到任何通讯。

如果确认信丢了，读者一小时后再从页脚订阅一次，会收到一封新的确认信。一小时内重复提交，只会看到"等待确认中"。

处理回复和退订

  • 读者回复通讯或确认信时，邮件寄到 newsletter@sjgart.org，由 Cloudflare 转发给负责人。直接在自己的邮箱里回复即可。
  • 读者可以用邮件底部的链接自行退订，无需处理。
  • 如果有人来信要求退订，在 EmailOctopus 的联系人里找到这个地址，把状态改为 Unsubscribed。
必须遵守
  • 不要在 EmailOctopus 后台手动添加或导入联系人，包括为了测试。测试一律用 Send test email。手动加入的地址没有"本人确认订阅"的记录，EmailOctopus 可能把名单当成未经同意收集的，进而限制账户发信。
  • 保持名单的双重确认（Double opt-in）开启。关掉后，订阅的人不用确认就会直接加入名单。

发送一期通讯

通讯只能在 EmailOctopus 后台编写和发送，目前由管理员操作：

  1. 登录 EmailOctopus，新建一个 Campaign，编辑器选 Code your own。
  2. 把模板 docs/subscribe-email.html 整份粘进去，再改写本期的正文、经文和链接。
  3. 发件人选 newsletter@sjgart.org，发件人名称填 St. John’s Gospel Arts。
  4. 填写主题（Subject），在设置里的 Preview text 填写收件箱预览文字。不要在 HTML 里自己写预览文字，EmailOctopus 会自动加入它的版本。
  5. 用 Send test email 寄一封测试信给自己，在手机和电脑上各看一遍。
  6. 确认无误后，发送给名单 Audience。
模板中必须保留
  • {{UnsubscribeURL}}：退订链接，必须放在文字上，不能放在图片上。
  • {{SenderInfoLine}}：寄件地址，显示 EmailOctopus 的伦敦代收地址，不会暴露任何人的住址。
  • {{RewardsURL}}：页脚的"Sent with EmailOctopus"，免费方案要求保留。

不要使用 {{ProfileURL}}：免费方案不支持，加上后邮件无法发送。

2联系表单

同工

访客在网站的"联系我们"页面填写姓名、邮箱和留言（10 到 2000 字）后，网站会寄出一封邮件：

发件人website@sjgart.org
收件人contact@sjgart.org，再由 Cloudflare 转发
主题Contact form: 访客姓名
正文访客的姓名、邮箱和留言，纯文本

回复访客

  1. 直接点邮箱里的"回复"。收件人会自动填成访客的邮箱，不是 website@sjgart.org。
  2. 发送前看一眼收件人栏，确认是访客的地址。

回复是从你自己的邮箱寄出的，访客会看到你的个人邮箱地址。Cloudflare 只转发收信，不能用 contact@sjgart.org 的名义回信。

同一个网络每分钟最多提交 5 次。访客如果看到"请稍后再试"，等一分钟即可。

3收信人管理

管理员

原则：网站只认职能地址，谁来收信由邮件系统决定。网站的 CONTACT_TO_EMAIL 固定为 contact@sjgart.org，增减同工时不要改它，也不需要重新部署网站。所有变更都在 Cloudflare 的 Email Routing 里完成。

Cloudflare 的界面位置：登录后选择账户，进入 Compute → Email Service → Email Routing，选择 sjgart.org。菜单名称可能随 Cloudflare 更新而变化。

A. 转发给另一位同工（一个人）

  1. 在 Destination Addresses 输入新同工的邮箱，提交。
  2. 新同工会收到 Cloudflare 的验证信，需要点 Verify email address。验证前无法选用这个地址。
  3. 在 Routing Rules 找到要改的地址（contact@ 或 newsletter@），编辑，把目标改成新同工的邮箱，保存。
  4. 从任意邮箱寄一封信到这个地址，确认新同工能收到。

每条规则只能转发给一个邮箱。改了以后，原来的收件人就收不到了。

B. 转发给多位同工：Email Worker（备选）

Email Worker 是在 Cloudflare 上运行的一小段程序，可以把一封信同时转给多个地址。收件人名单放在 Worker 的变量里，以后增减同工只改这个变量，不改代码。

  1. 把每位同工的邮箱都按 A 的第 1、2 步加入 Destination Addresses 并完成验证。没验证的地址收不到转发。
  2. 在 Email Routing 的 Email Workers 页创建一个 Worker，名称例如 sjgart-forward。也可以在 Workers & Pages 里创建。
  3. 把 Worker 的代码替换为下面这段，部署： 
    // 把收到的信转发给 RECIPIENTS 里的每个地址。
export default {
  async email(message, env) {
    const recipients = (env.RECIPIENTS ?? "")
      .split(",")
      .map((address) => address.trim())
      .filter(Boolean);

    // 一个地址失败不影响其他人收到。
    await Promise.allSettled(recipients.map((to) => message.forward(to)));
  },
};
  4. 在这个 Worker 的 Settings → Variables and Secrets 里添加变量 RECIPIENTS，值是用英文逗号分隔的邮箱，例如：
    you@example.com, member@example.com
  5. 回到 Routing Rules，编辑 contact@（或 newsletter@）的规则：Action 选 Send to a Worker，Destination 选这个 Worker，保存。
  6. 寄一封测试信到这个地址，确认名单上的每个人都收到。

以后增减同工：先验证新地址，再修改 RECIPIENTS 并保存。Cloudflare 保存变量时会自动重新部署 Worker，网站本身不受影响。

C. 转发给一个群组（备选）

建一个 Google 群组，把同工加为成员，允许外部来信，再按 A 的步骤把 Cloudflare 的目标设为群组地址。以后增减同工只需在群组里改成员。不用写代码，但要多管理一个 Google 群组。

以后：非营利资格

事工取得非营利资格后，可以申请 Google Workspace 或 Microsoft 365 的公益版。届时同工会有真正的 sjgart.org 邮箱，也能以 contact@sjgart.org 的名义回信。迁移时只需把 Cloudflare 的转发换掉（或把 MX 记录交给新服务），网站不用改。

4配置备忘

管理员

Vercel 环境变量

在 Settings → Environment Variables 中设置。本地开发用项目根目录的 .env.local。修改后必须重新部署（Deployments → Redeploy）才生效。

变量用途取值
EMAILOCTOPUS_API_KEY页脚订阅EmailOctopus → Integrations & API 中的密钥
EMAILOCTOPUS_LIST_ID订阅加入的名单名单 Audience 的 ID
RESEND_API_CONTACT_KEY联系表单发信Resend 中的 API 密钥
CONTACT_FROM_EMAIL表单邮件的发件人St. John’s Gospel Arts <website@sjgart.org>
CONTACT_TO_EMAIL表单邮件的收件人contact@sjgart.org，固定不改
NEXT_PUBLIC_SITE_URL分享链接的网址https://www.sjgart.org

EmailOctopus 设置

  • 域名：sjgart.org 已验证。
  • 账户名称：St. John’s Gospel Arts（Brand → Information）。
  • 寄件地址：Sender info 中开启隐藏地址（Private Address），邮件显示 EmailOctopus 的代收地址。
  • 名单 Audience：Consent & customisation → Double opt-in email 已开启。确认信只能用富文本编辑，不能粘 HTML；发件人为 newsletter@sjgart.org。
  • 成功页：同一页的 Success page，设置了标题和正文。
  • 检查工具：在项目目录运行 node scripts/check-emailoctopus.mjs，只读检查密钥、名单和双重确认是否开启。

Cloudflare DNS（sjgart.org）

  • MX：指向 Cloudflare Email Routing（route1/2/3.mx.cloudflare.net），所以收信由 Cloudflare 负责。
  • SPF：v=spf1 include:_spf.mx.cloudflare.net ~all。一个域名只能有一条 SPF 记录；以后要加其他服务，把它的 include: 合并进这一条。
  • DMARC：v=DMARC1; p=none;，只监测，不拒收。
  • DKIM：EmailOctopus 和 Resend 各自验证域名时添加的记录，不要删除。

Email Routing 规则

  • contact@sjgart.org → 负责人的邮箱
  • newsletter@sjgart.org → 负责人的邮箱

5常见问题

同工
读者说收不到确认信
请对方等几分钟，并查看垃圾邮件和"其他"文件夹。还是没有的话，一小时后从页脚重新订阅一次。
页脚订阅显示"订阅未能完成"
交给管理员处理。先查 Vercel 上的 EMAILOCTOPUS_* 变量，再看 Vercel 日志中以 [subscribe] 开头的记录。
"联系我们"提交失败
交给管理员处理。先查 Vercel 上的 RESEND_API_CONTACT_KEY、CONTACT_FROM_EMAIL、CONTACT_TO_EMAIL，再看日志中以 [contact] 开头的记录。
表单提交成功，但没人收到留言
问题在转发这一段。检查 Cloudflare 里 contact@ 的规则，以及目标地址是否已验证。
通讯页脚的地址为什么在伦敦
这是 EmailOctopus 提供的代收地址。法规要求营销邮件附上寄件地址，用它可以不公开任何人的住址。
